# Phase 07.1: Fix multi-tab session takeover regression - Context

**Gathered:** 2026-09-16

<domain>
## Phase Boundary

Restore the multi-tab session-takeover notification/eviction behavior that was
a working Phase 4 deliverable (`04-02-PLAN.md`) and got silently dropped during
the Phase 7 monolith-to-N-tier split. This is a regression fix, not new
capability — no design decisions, only restoring previously-decided behavior
on the new architecture.

No interactive discussion was run for this phase: `/gsd-audit-milestone`
already fully diagnosed root cause, exact fix location, and verified the
event plumbing exists — there are no product-level gray areas left to
resolve, only a mechanical restore. This matches discuss-phase's own "skip
assessment" criterion (clear-cut implementation, already decided elsewhere).

</domain>

<decisions>
## Implementation Decisions

### Root cause (from v1.0-MILESTONE-AUDIT.md, independently re-verified this session)
- **D-01:** `apps/engine/src/rooms/manager.ts` `rejoinPlayer()` (lines
  209-267) reassigns `room.players` from `oldPlayerId` to `newPlayerId` but
  never notifies or closes the superseded socket. Pre-Phase-7, this was
  handled in `apps/server/src/rooms/manager.ts:135-152` (commit `802ba24~1`):
  send `session_taken_over` to the old socket, then `ws.close(1000, "Session
  taken over by another tab")`. Confirmed via grep: zero matches for
  `"session_taken_over"` in `apps/engine/src` or `apps/gateway/src` — the
  client (`apps/web/src/App.tsx:117`, `apps/web/src/net/race-client.ts:308-311`)
  still fully implements the consumer, currently dead code.

### Fix mechanism
- **D-02:** Use the existing `EngineToGatewayEvent` types — `send_to_client`
  and `disconnect_client` — already implemented and working in
  `apps/gateway/src/ws/handlers.ts:58-78` (confirmed this session by direct
  read). No new wire-protocol work needed; `sessionTakenOverSchema` already
  exists in `packages/shared/src/messages.ts:292`. — **Reversibility:**
  reversible — purely additive, two `bridge.publishToGateway()` calls.
- **D-03:** In `rejoinPlayer()`, when `oldPlayerId !== newPlayerId` (existing
  branch at line ~230), before/while reassigning `room.players`: publish
  `send_to_client{playerId: oldPlayerId, payload: {type: "session_taken_over"}}`
  then `disconnect_client{playerId: oldPlayerId, code: 1000, reason: "Session
  taken over by another tab"}` — matching the exact pre-Phase-7 behavior and
  message/close-code pair, so no other code (client toast copy, close-code
  handling) needs to change.
- **D-04:** No new EventBridge event types, no schema changes. This is a
  same-tier code change inside `apps/engine`, using events that already
  cross the bridge correctly (confirmed for unified, split-IPC, and Redis
  modes in the Phase 7 verification and this milestone's integration check).

### Claude's Discretion
- Exact statement ordering/wording of the two `publishToGateway` calls, and
  whether to guard with the same `oldPlayerId !== newPlayerId` check already
  present in the function (yes — reuse it, don't duplicate the condition).
- Regression test placement — mirror the existing reconnect/rejoin test
  suite structure in `apps/engine/src/__tests__/reconnect.test.ts`.

</decisions>
