# Phase 03.1 Context: Wire word-correctness into output frame

**Inserted after Phase 3** to close a gap found by automated goal-backward
verification during v1.0 milestone close (03-VERIFICATION.md, gsd-verifier).

## Diagnosed gap (no discuss-phase needed — root cause and fix location already known)

`aggregateWordCorrectness` / `isWordCorrect` in `apps/engine/src/race/scoring.ts`
are correctly implemented and unit-tested (6 passing tests in
`scoring.test.ts`) but are **never called anywhere outside their own test
file** — not in `buildRaceEndFrame`, not in any wire frame sent to clients,
not rendered anywhere in `apps/web`. No player ever sees per-word
correctness, even though ROADMAP.md Phase 3 Success Criterion 1 and
REQ-05 ("Per-word correctness + backspace handling for accurate WPM
calculation") call for it.

This is NOT a documented/deliberate scope cut — no CONTEXT.md, decision log,
or UAT note anywhere disclaims this. It reads as incomplete wiring left over
from Phase 3.

## Required fix

Wire the existing `aggregateWordCorrectness`/`isWordCorrect` functions into
the actual race state / wire protocol so word-correctness is computed
server-side and reaches the client (either included in the existing
char-state broadcast frame, or a new field on it — whichever fits the
current `apps/engine`/`apps/gateway`/`apps/web` wire contract with the least
churn). Render it client-side per Phase 3's original spec ("word shows
correct only when ALL chars end `correct`").

Do not change the underlying per-char state model (that's Phase 03 Gap A,
a separate documented/accepted deviation — out of scope here).

## Success criteria

- `aggregateWordCorrectness`/`isWordCorrect` (or their current call sites)
  are invoked from real race-state production code, not only from
  `scoring.test.ts`.
- A new or existing test proves per-word correctness reaches the client via
  the wire protocol (unit or integration level).
- No regression in existing engine/gateway/web test suites.
