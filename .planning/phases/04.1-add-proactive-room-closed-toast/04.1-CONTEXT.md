# Phase 04.1 Context: Add proactive room-closed toast

**Inserted after Phase 4** to close a gap found by automated goal-backward
verification during v1.0 milestone close (04-VERIFICATION.md, gsd-verifier).

## Diagnosed gap (no discuss-phase needed — root cause and fix location already known)

ROADMAP.md Phase 4 Success Criterion 3 requires: "Idle rooms (>10min no
activity) are evicted by a 60s sweeper; opponent views show graceful 'room
closed' toast within 5s of last player leaving."

The idle-sweeper half of this criterion was explicitly descoped by user
decision D-09 in `.planning/phases/04-reconnect/04-CONTEXT.md` ("User
explicitly requested no idle eviction") — that part is accepted, out of
scope for this closure phase.

The "room closed" toast half is a **separate, undocumented gap**: the only
related UX today is a reactive "Room Lost" error toast shown when a client's
own next action (e.g. a keystroke or reconnect attempt) fails against a room
that no longer exists — not a proactive push notification to an idle
viewer within 5s of the last other player leaving. This was never discussed
as excluded scope and has no coverage in Phase 5's toast set either.

## Required fix

When the last remaining player leaves/disconnects from a room (the room
becomes empty and is about to be cleaned up / evicted), proactively push a
"room closed" notification to any other still-connected client viewing that
room (e.g. a spectator or a tab left open on the results screen), so they
see the toast within ~5s — not only reactively on their next failed action.
Wire this through the existing `apps/engine` → `apps/gateway` →
`apps/web` toast pipeline (see Phase 5's `ToastQueue`/error-toast pattern
for the established mechanism).

## Success criteria

- A proactive "room closed" toast fires for any connected client left in a
  room once it becomes empty, without requiring that client to take an
  action first.
- Test coverage (unit or integration) proves the proactive push, not just
  the existing reactive error-toast path.
- No regression in existing engine/gateway/web test suites.
