## Skip Rationale

No gray areas were presented to the user. This phase exists to close a gap
found by `/gsd-audit-milestone` during v1.0 milestone close: the multi-tab
"session takeover" notification (a working Phase 4 deliverable) was silently
dropped when Phase 7 split the monolithic `apps/server` into
`apps/engine`/`apps/gateway`. The audit (independently re-verified via direct
code read + grep in this session) fully diagnosed:

- exact root cause (`rejoinPlayer()` never publishes `session_taken_over`/
  `disconnect_client` for the superseded `playerId`)
- exact fix (two `bridge.publishToGateway()` calls using event types that
  already exist and already work correctly on the gateway side)
- the historical reference implementation to match (pre-Phase-7
  `apps/server/src/rooms/manager.ts:135-152`)

This is a restore-to-previously-decided-behavior fix with no product-level
ambiguity — matches discuss-phase's own skip-assessment criterion ("no
meaningful gray areas exist... the phase may not need discussion").
