# Phase 03.1 Plan 01: Wire word-correctness into output frame Summary

**Wired the already-implemented but orphaned `aggregateWordCorrectness`/`isWordCorrect` scoring functions into the actual server→client wire protocol and rendered per-word correctness visually on the race track.**

## Accomplishments
- `buildCursorUpdateFrame` and `buildRejoinedRoomFrame` (apps/engine/src/race/frames.ts) now compute `words: {start,end,correct}[]` from `aggregateWordCorrectness` and include it on the wire.
- `packages/shared/src/messages.ts` schema extended: `words` optional on `cursorUpdateSchema`, required on `rejoinedRoomSchema`'s `you`/`players` entries.
- `apps/web`'s race store/client thread `ownWords` through to `RaceView`, which applies `word-correct`/`word-incorrect` CSS classes via a `useMemo` char-index lookup — additive to the existing per-char state class, no DOM restructuring.
- Added CSS rules for `.word-correct`/`.word-incorrect` (apps/web/src/styles.css) — these classes existed in the DOM but had no visual effect until this fix; without it the wiring would still have been invisible to players.
- Full verify chain green: typecheck clean (4 workspaces), 154/154 backend tests, 85/85 web tests.
