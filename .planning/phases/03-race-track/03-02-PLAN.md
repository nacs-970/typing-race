## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Browser → WS → dispatch.keystroke | Untrusted client keystroke; server validates + computes char-state; server is authoritative (Pitfall 1 + V5) |
| Browser → WS → dispatch.cursor_position | Untrusted client cursor position; cursor_position schema does NOT carry charStates/wpm — server cannot accept spoofed correctness |
| Server cursor_update broadcast → all browsers | Server-authoritative charStates + wpm; clients render but do not compute |

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-03-05 | Tampering / Spoofing | inbound cursor_update (none — frame is server-only) | low | mitigate | cursor_update schema is optional() for charStates/wpm; the schema INBOUND discriminator does not include cursor_update (Phase 2 inbound union only has cursor_position — charStates/wpm never cross the inbound boundary). JSDoc above cursorUpdateSchema documents this invariant. Server is sole producer; clients render-only. |
| T-03-06 | Tampering | client sends charStates/wpm in some other inbound frame | low | mitigate | Inbound union (clientToServerSchema) does not include cursor_update. cursor_position schema explicitly omits charStates/wpm. dispatch.keystroke ignores any inbound charStates/wpm (only reads frame.index, frame.char, frame.clientTs per Phase 2). |
| T-03-07 | Information Disclosure | charStates broadcast reveals position | low | accept | Opponent cursors already broadcast position; charStates is the SAME information plus 2 bits/char — public by design (D-02 intent: opponents see your green/red cursors) |
| T-03-08 | Tampering | wrong-char keystroke increments totalKeystrokes (false accuracy inflation) | low | accept | By design: totalKeystrokes = ALL accepted keystrokes including errors (D-06: correctChars / totalKeystrokes). Errors ARE keystrokes. Documented in scoring.ts JSDoc. |
