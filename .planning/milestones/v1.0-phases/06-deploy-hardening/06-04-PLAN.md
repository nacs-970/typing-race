<objective>
Render the SERVER_SHUTTING_DOWN error frame (server-side broadcast wired in 06-01) as a distinct, friendly client-side toast instead of letting it fall through to the generic error fallback.

Purpose: 06-01 broadcasts the SERVER_SHUTTING_DOWN error frame to every connected client on drain, but broadcasting it server-side is not the same as a "graceful toast" (ROADMAP Phase 6 criterion #1) — the client must recognize the code and show a purpose-built message. This is split out from 06-01 as its own plan because it is the one task in that plan's scope with no coupling to the cross-tier drain tracer: it only needs the already-typed `SERVER_SHUTTING_DOWN` error code from `packages/shared/src/messages.ts` (landed by 06-01's Task 1), not any Engine/Gateway wiring, keeping 06-01's file footprint tight to its actual cross-tier concern.

Output: a `SERVER_SHUTTING_DOWN` branch in App.tsx's error-handling chain producing a distinct title/body toast.
</objective>
