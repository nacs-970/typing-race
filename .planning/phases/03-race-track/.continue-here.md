## Critical Anti-Patterns

| Pattern | Description | Severity | Prevention Mechanism |
|---------|-------------|----------|---------------------|
| RaceView backspace ignore | `if (ev.key.length !== 1) return;` filter is too aggressive — drops Backspace, Delete, Arrow keys, modifier-only presses. Typing-race UX requires backspace to fix typos without losing the position. | blocking | Replace length filter with explicit per-key handling: backspace = correction, single-char = keystroke, modifier = ignore. |
| RaceView buffer is local-only | `buffer` state tracks "what I just typed" but is never sent to server; on remote ack the charStates overlay may not match what user sees locally. | advisory | Make `ownCharStates` (server-confirmed, in useRaceStore) drive the visual; use local `buffer` only as an optimistic "what the user is typing RIGHT NOW" overlay until the server's cursor_update arrives. |

## Critical Anti-Patterns (do NOT repeat these)

- **RaceView backspace ignore**: client handler rejects all non-single-char keys → can't delete. Mitigation: explicit per-key handling. STRUCTURAL: add a `if (ev.key === 'Backspace')` branch BEFORE the `length !== 1` filter.
- **Cursor advance vs cursor display conflation**: user reads cursor as "last typed position" but code places it at "next to type". Mitigation: either re-render the cursor at `ownIndex` (last typed) instead of `ownIndex + 1`, OR keep current and rename the indicator so it's clear.
