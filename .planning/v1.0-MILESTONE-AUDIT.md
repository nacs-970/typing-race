## Integration Check (gsd-integration-checker + agy cross-check)

Full E2E flow (create → join → ready → countdown → race → keystrokes → race end → rematch)
re-confirmed wired end-to-end through the current `apps/web`/`apps/gateway`/`apps/engine`
split. `apps/server` (pre-Phase-7 monolith) remains fully retired.

**Multi-tab session takeover flow — now WIRED** (previously the sole blocker):
1. `manager.ts:230` — `isMultiTabTakeover` computed once from `oldPlayerId !== newPlayerId`.
2. `manager.ts:233-241` — re-keys the only three `PlayerId`-scoped fields (`room.players`, `hostId`, `firstFinisherId`); confirmed no other player-keyed state exists, so REQ-RESULTS/REQ-CURSOR are unaffected.
3. `manager.ts:249-261` — publishes `send_to_client{session_taken_over}` then `disconnect_client` for `oldPlayerId`, gated by `isMultiTabTakeover` (test 5 proves the same-socket retry path does not fire this).
4. `packages/shared/src/bridge.ts` — both in-memory and Redis event bridges are untyped JSON pass-throughs; no per-event-type gap in the N-tier transport.
5. `apps/gateway/src/ws/handlers.ts:58-80` — relays `send_to_client`/`disconnect_client` to the correct socket by `playerId` lookup.
6. `apps/web/src/net/race-client.ts:308-311,99` — old tab receives `session_taken_over`, sets a flag that suppresses auto-reconnect.
7. `apps/web/src/App.tsx:117,229-238,271,286,326-337` — renders "session active in another tab" banner with a working reclaim action.
8. Eviction-safety: the resulting `client_disconnected` publish from the closed socket no-ops in `handlePlayerDisconnect` because `oldPlayerId` was already deleted from `room.players` earlier in the same synchronous call — no phantom "opponent disconnected" broadcast to other players.
