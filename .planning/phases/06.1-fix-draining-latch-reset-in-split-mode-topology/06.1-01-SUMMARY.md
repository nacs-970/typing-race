# Phase 06.1 Plan 01: Fix draining latch reset in split-mode topology Summary

**Fixed a real production-breaking bug: `ClientManager.isDraining()` never reset after an engine-only crash-restart in split-mode topology, permanently disabling room creation on an otherwise-healthy gateway. Flagged as CR-B1 in code review, explicitly scoped out as "pre-existing," never actually fixed — closed here.**

## Accomplishments
- `ClientManager` gained `ownDrainStarted`/`markOwnDrainStarted()`/`hasOwnDrainStarted()`, reset in `clear()`.
- `apps/gateway/src/index.ts`'s `drain()` now calls `manager.markOwnDrainStarted()` synchronously, before any `await`, at the top of its drain IIFE.
- `apps/gateway/src/ws/handlers.ts`'s `"drained"` event handler now resets `manager.setDraining(false)` only when `!manager.hasOwnDrainStarted()` — i.e. only for an independent, unrelated drain cycle (engine-only restart), never for the gateway's own shutdown.
- New regression test in `drain.test.ts` proves an independent engine-only restart no longer wedges the gateway; the existing "E2E contract" test updated to call `markOwnDrainStarted()` so it correctly represents an owned/unified-mode cycle, with its original assertions unchanged.
- Full verify chain green: typecheck clean, 154/154 backend tests (including the new regression test), 85/85 web tests.
