# Phase 1 — Plan 03: Fly.io Deploy Infrastructure (Build Only, Not Deploy — REQ-12)

<objective>
Build the deploy infrastructure (Dockerfile + fly.toml + deploy script + .dockerignore) so that when Phase 6 executes, a single `scripts/deploy.sh` produces a live Fly.io URL serving SPA + WS + /health. This plan **does NOT execute `fly deploy`** — it only builds and locally-verifies the deploy artifacts via `docker build` + `docker run`. The Phase 6 plan owns the actual Fly.io account setup, `fly auth login`, and live `fly deploy`.

Purpose: REQ-12 (Fly.io single-process deploy) needs a verified deploy artifact before any game logic stacks on. A broken Dockerfile at Phase 6 means a broken resume URL — find that bug now, in Phase 1, on a laptop, not at deploy time. Local Docker verification is the canonical pre-flight for Fly: same Bun runtime, same entrypoint, same port; the only difference from Fly is the edge proxy.

Output:
- `Dockerfile` (multi-stage, oven/bun:1.4.0-slim, non-root user, WORKDIR matches `import.meta.dir` path)
- `.dockerignore` (excludes node_modules, dist, git, planning, logs, env)
- `fly.toml` (single-process config: kill_signal, internal_port, env, health check, WS-friendly concurrency, scale-to-zero, 256mb shared-cpu-1x)
- `scripts/deploy.sh` (executable pre-flight + deploy command print, no auto-deploy)
- README `## Deploy (Phase 6, not now)` section
- Verified: `docker build` succeeds; `docker run` boots Bun in container; SPA + WS + /health all serve on :8080 inside container
</objective>
