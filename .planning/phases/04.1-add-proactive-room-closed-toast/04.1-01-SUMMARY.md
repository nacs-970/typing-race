# Phase 04.1 Plan 01: Add proactive room-closed toast Summary

**Added a proactive "Room Closed" push notification, fired when a room's last player leaves, reaching any other still-connected client (e.g. a spectator or a tab left open on results) within the same broadcast cycle — not only reactively on that client's next failed action.**

## Accomplishments
- `RoomManager.removePlayer()` (apps/engine/src/rooms/manager.ts) now publishes a `broadcast_to_room` event with `{type: "error", code: "ROOM_CLOSED", ...}` when `room.players.size === 0`, before the room is deleted from the store.
- Publish ordering confirmed correct: fires AFTER the leaver's own `player_room_cleared` publish, so the leaver's own socket (already untracked on the gateway side by then) never receives its own room's closed notice — no phantom self-notification.
- `apps/web/src/App.tsx` maps the new `ROOM_CLOSED` error code to a "Room Closed" / "All players have left this room." toast via the existing error-toast pipeline.
- New regression test (`rooms.test.ts` #9) proves the broadcast fires purely from `removePlayer()` being called — a push, not a reactive fallback.
- Full verify chain green: typecheck clean, 154/154 backend tests, 85/85 web tests.
