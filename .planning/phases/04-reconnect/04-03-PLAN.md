<objective>
Implement WebSocket heartbeat ping/pong (15s ping / 5s timeout) to detect dropped or zombie connections, and in-memory per-IP rate limiting (10 room creations/hour) to protect server resources. (Note: idle room sweeper explicitly omitted per user decision).

Purpose: Fulfill REQ-09 success criteria 4 and 5 (heartbeat ping/pong, per-IP rate limiting).
</objective>

<tasks>

### Task 1: WS heartbeat ping/pong
- In `apps/server/src/index.ts` & `apps/server/src/ws/handlers.ts`:
  - Track `ws.data.lastPongAt = Date.now()` on open.
  - Every 15s, iterate active server sockets and send ping.
  - If `now - ws.data.lastPongAt > 20_000` (15s ping interval + 5s pong timeout), terminate dead socket via `ws.close(1001, "Heartbeat timeout")`.
  - Handle pong responses by updating `ws.data.lastPongAt = Date.now()`.

### Task 2: In-memory per-IP rate limiter
- In `apps/server/src/rooms/manager.ts`:
  - Create `class IpRateLimiter`:
    - Sliding window: max 10 creations per IP per 3600s (1 hour).
    - Method `checkAndConsume(ip: string): boolean`.
    - Auto-cleans expired entries to prevent memory buildup.
- In `apps/server/src/ws/dispatch.ts`:
  - In `case "create_room"`:
    - Extract client IP from `ws.data.remoteAddress` or forwarded header.
    - If `rateLimiter.checkAndConsume(ip)` returns false:
      - Send error `{ type: "error", code: "RATE_LIMITED", message: "Too many rooms created from this IP. Limit is 10 per hour." }`.
      - Return early.
- Write unit tests in `apps/server/src/__tests__/rate-limit.test.ts`:
  - Verify 10 creations allowed, 11th rejected.
  - Verify independent IP limits.
  - Verify reset after 1 hour.
</tasks>
