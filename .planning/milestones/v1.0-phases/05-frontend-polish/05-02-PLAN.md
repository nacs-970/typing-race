<threat_model>
ASVS Level 1 Threat Model:
1. Threat: Cross-Site Scripting (XSS) via unescaped player nickname injection in floating micro-tags.
   - Severity: High (Mitigated).
   - Mitigation: CursorManager generates micro-tags using native DOM elements and sets `tag.textContent = nickname` (never `innerHTML`). Nicknames are strictly text nodes, preventing script execution or HTML tag injection. Long nicknames are clamped to 16 characters max to prevent DOM layout overflow attacks.
2. Threat: Forced Synchronous Layout / Layout Thrashing Denial of Service in the animation loop.
   - Severity: High (Mitigated).
   - Mitigation: Absolutely zero DOM reads (`getBoundingClientRect`, `offsetLeft`, `offsetWidth`, `getComputedStyle`) are permitted inside `CursorManager.renderFrame()`. All character-to-(x, y) mappings are computed via pure cached arithmetic from `PassageLayout`.
3. Threat: CSS Injection / Prototype Pollution via dynamic color scales.
   - Severity: Low (Mitigated).
   - Mitigation: Cursor colors are strictly looked up from a hardcoded, immutable 8-color pastel rainbow array (`PASTEL_RAINBOW_COLORS`) indexed by `(slotIndex % 8)`.
</threat_model>

<action>
1. Create `apps/web/src/core/layout.ts` per Pattern 1 and UI-SPEC resolved consideration (long-text: Passage Corpus Card):
   - Import `prepareWithSegments`, `layoutWithLines`, and type `PreparedTextWithSegments` from `@chenglou/pretext`.
   - Export interface `LineRange { start: number; end: number; width: number; y: number; }`.
   - Export class `PassageLayout`:
     - Properties: `prepared: PreparedTextWithSegments | null`, `lineRanges: LineRange[]`, `charWidth: number = 9.6`, `lineHeight: number = 32`, `containerWidth: number = 800`.
     - Method `init(passageText: string, font: string, lineHeight: number): void`:
       - Sets `this.lineHeight = lineHeight`.
       - Calls `this.prepared = prepareWithSegments(passageText, font)`.
       - Measures monospace character advance `this.charWidth = ctx.measureText("M").width` using Canvas 2D.
     - Method `updateLayout(containerWidth: number): LineRange[]`:
       - Returns `[]` if `!this.prepared`.
       - Stores `this.containerWidth = containerWidth`.
       - Calls `layoutWithLines(this.prepared, containerWidth, this.lineHeight)`.
       - Maps lines into `lineRanges` with cumulative char index offsets `start` and `end`, width, and vertical offset `y = idx * lineHeight`.
     - Method `getCoordinates(progressIndex: number): { x: number; y: number }`:
       - Resolves which `LineRange` contains `progressIndex`.
       - Calculates column offset `col = progressIndex - range.start`.
       - Clamps `x` to container bounds (`Math.min(col * charWidth, containerWidth)`).
       - Returns `{ x: col * this.charWidth, y: range.y }` in $O(1)$ without any DOM queries.
     - Method `getLineRanges(): readonly LineRange[]`.
2. Create `apps/web/src/__tests__/layout.test.ts`:
   - Set up Happy-DOM Canvas 2D mock in `beforeAll` (`HTMLCanvasElement.prototype.getContext("2d")` returning mock `measureText`).
   - Test `PassageLayout.init()` with sample 50-word passage.
   - Test `updateLayout(800)` splits text into multiline ranges without gaps.
   - Test `getCoordinates()` returns monotonically increasing `x` within a line, and advances `y` on line wraps.
   - Verify coordinate lookup executes in <0.005ms per call with zero DOM reads.
</action>
