# Phase 2 — Plan 03: Clock Sync (NTP-style) + Server-Authoritative Countdown (REQ-03)

<objective>
Implement a two-phase NTP-style clock synchronization so that two clients (potentially with skewed local clocks) start the race at the same moment in the server's reference frame. Add an HTTP `GET /api/clock-sync` endpoint as the primary path; the WS `clock_sync` frame from Plan 01 stays as a backup. The `joined_room` frame already carries `clockOffsetMs` (Plan 02 wired it) — the client uses this to gate the countdown UI on `(startsAtServerMs - clockOffsetMs)` rather than the local clock. The countdown display ticks down based on server time, not local time.

Purpose: clock-sync drift is one of the high-confidence pitfalls flagged in research — without it, players with faster clocks start typing 200-500ms earlier and inflate their WPM by 10-15%. The fix is server-authoritative: the server decides when the race starts (`startsAtServerMs`); the client just translates that to its own clock for display. This plan makes both the math and the UI correct.

    /**
     * Two-phase NTP-style clock sync over HTTP.
     *   t0 = client send time
     *   t1 = server receive time  (from response)
     *   t2 = server send time     (from response)
     *   t3 = client receive time
     *   offset = ((t1 - t0) + (t2 - t3)) / 2
     *   roundtrip = (t3 - t0) - (t2 - t1)
     *
     * If roundtrip > 500ms, retry once. If still > 500ms, throw.
     */
    export type ClockSyncResult = {
      offsetMs: number;
      roundtripMs: number;
    };

    export async function syncClock(
      fetchImpl: typeof fetch = fetch,
      url = "/api/clock-sync",
    ): Promise<ClockSyncResult> {
      const attempt = async (): Promise<ClockSyncResult> => {
        const t0 = Date.now();
        const res = await fetchImpl(url);
        if (!res.ok) throw new Error(`clock-sync HTTP ${res.status}`);
        const { t1, t2 } = (await res.json()) as { t1: number; t2: number };
        const t3 = Date.now();
        const roundtripMs = (t3 - t0) - (t2 - t1);
        const offsetMs = ((t1 - t0) + (t2 - t3)) / 2;
        return { offsetMs, roundtripMs };
      };

      const first = await attempt();
      if (first.roundtripMs <= 500) return first;
      const second = await attempt();
      if (second.roundtripMs <= 500) return second;
      throw new Error(`clock-sync roundtrip too high: ${second.roundtripMs}ms`);
    }
    ```

    import { useEffect, useState } from "react";
    import { useClockStore } from "../store/clock.ts";

    /**
     * Server-time-anchored countdown. The displayed seconds remaining is
     * derived from (startsAtServerMs - clockOffsetMs - Date.now()), so a
     * client with a 5s clock skew still sees the correct countdown.
     */
    export function CountdownView({ startsAtServerMs }: { startsAtServerMs: number }): React.ReactElement {
      const offsetMs = useClockStore((s) => s.offsetMs);
      const [seconds, setSeconds] = useState(() =>
        Math.max(0, Math.ceil((startsAtServerMs - offsetMs - Date.now()) / 1000))
      );

      useEffect(() => {
        const id = setInterval(() => {
          const remaining = Math.max(0, (startsAtServerMs - offsetMs - Date.now()) / 1000);
          setSeconds(Math.ceil(remaining));
          if (remaining <= 0) clearInterval(id);
        }, 100);
        return () => clearInterval(id);
      }, [startsAtServerMs, offsetMs]);

      return <div className="countdown">Starting in {seconds}…</div>;
    }
    ```
